Cloudflare

Browser

Desktop or phone. Pages render on the server; forms post without JavaScript.

Access optional

Cloudflare Access login in front of the whole host. Adds a signed JWT to each request.

Ruby Worker

One Worker: SvelteKit server rendering, form actions and API routes.

HR field encryption

AES-256-GCM in the Worker, keyed by the secret HR_DATA_KEY. Values leave it only as ciphertext.

Every request, in order

  1. 1CSRF checkCross-site form posts are refused.
  2. 2HTTPS onlyPlain HTTP is redirected on a deployed host.
  3. 3Access JWTRS256 against the team's keys; fails closed unless turned off.
  4. 4SessionOpaque cookie; only its hash is stored in D1.
  5. 5RouterequireUser or requireAdmin, then load or action.

D1 database

Cloudflare's SQLite database, in your own account.

  • HR fields stored as ciphertext
  • Projects, tasks, labels, milestones
  • Knowledge-base pages and revisions
  • Comments and notifications
  • People, time off, HR audit log
  • Users, invites, hashed sessions
  • FTS5 search: pages_fts, tasks_fts
  • Numbered SQL migrations in migrations/

R2 bucket

Attachments, up to 25 MB each. A private bucket: files are served only through the Worker, to signed-in people.

Object keys come from the server, never from file names.
