## Security pass
- Markdown: release bodies reach the DOM only via `Markdown.svelte` -> `renderMarkdown` (`src/routes/(app)/releases/+page.svelte:30`). Titles, dates, versions are text-interpolated by Svelte. No other `{@html}` added. PASS.
- `_headers`: root file is only a `/_app/version.json` rule (`! Cache-Control`, `no-store`). Built `.svelte-kit/cloudflare/_headers` before = the two autogenerated SvelteKit blocks; after = same two blocks plus the new rule at the top. Nothing removed or changed. `_headers` applies only to static-asset responses from the ASSETS binding; HTML pages are served by the worker, where `src/lib/server/security-headers.ts` sets HSTS, nosniff, Referrer-Policy, COOP, Permissions-Policy, X-Robots-Tag and SvelteKit sets the CSP. The file cannot touch those. Note `/_app/*` also adds `Cache-Control: no-cache` after the new rule, so version.json should be served `no-store, no-cache` (still no-store); not checkable without a deploy. PASS.
- `/releases` auth: lives in `(app)`; signed-out GET returns 303 to `/login?next=%2Freleases` (verified by my spec). Not public; fine. Note the release text is also in the client JS bundle (static assets, `/_app/immutable/*`, behind Access on the deployed host): content is non-sensitive staff notes. PASS.
- localStorage: every read and write in `release-seen.svelte.ts` is try/catch; read runs in `onMount`, not SSR. Test with a throwing `localStorage` getter: no page error. PASS.
- Reload loops: `beforeNavigate` sets `location.href` only on a navigation the user triggered, only when `updated.current` is true and `!willUnload`; it never reloads by itself. `reload()` and the dialog are click-driven. Poll failure leaves `updated` false (no banner, no reload). Version changing every poll just keeps the banner up; after a full load the new page starts with `updated` false. No loop. Minor: it does not call `cancel()`, so the client navigation also starts; harmless. Dirty forms: nav after update discards unsaved input without asking (full load on link click); the PRD only asks for the Reload button confirm, so accepted.
- Logging: no `console.*` in the new src files. `scripts/deploy.ts` console output is the existing CLI pattern. PASS.
