# RUBY engineering checklist

Recurring defect classes. The D1, web and test items are carried over from earlier projects' pipelines, where
each one cost a fix cycle; the role, soft-delete, search, Markdown, attachment and Access items are specific to Ruby.
Engineers check every change against this list before handing it to QA; QA and the red team check the diff against
it. Add an item whenever a finding repeats, and name the helper to reuse.

## Data access (D1)

- **100 bound parameters per statement.** Never `inArray(col, list)` with a list that can grow. Bind the list once
  as JSON: `col IN (SELECT value FROM json_each(?))`. Test with 101+ ids.
- **LIKE and GLOB patterns.** D1 rejects a pattern longer than 50 bytes. Use `instr(lower(col), ?) > 0` for
  substring search. Test with a 60-character term.
- **Concurrent writes.** A read-then-write that depends on state is one guarded statement (`UPDATE … WHERE …
RETURNING`, `INSERT … SELECT … WHERE NOT EXISTS`) inside one `db.batch`. Prove it with a concurrent test.
- **Bounded work.** Every scan has a row cap and a period; aggregates are computed in SQL, not by loading all rows.
  Lists are paginated.
- **Migrations.** Never edit an applied one; re-runnable; RUNBOOK notes the D1 Time Travel bookmark before a
  remote apply. A migration that touches a table with FTS triggers updates the triggers in the same file.
- **Timestamps.** UTC milliseconds as integers; one shared `now()` helper; no local-time strings in the database.

## Roles, access and Cloudflare Access

- **One access rule.** Every load, action, API route and download starts with `requireUser` or `requireAdmin`.
  Admin pages and admin actions use `requireAdmin`; a member gets 403 and a signed-out request gets the sign-in
  redirect. Hidden and missing ids get the same answer (status, body, timing): no existence oracle.
- **Deactivated users.** A deactivated user's sessions are rejected on the next request. The last active admin cannot
  be deactivated or demoted; prove it with a concurrent test.
- **Access JWT.** Signature (pinned algorithm, team JWKS), `aud`, issuer and expiry are verified. On a deployed host a
  missing header or missing `ACCESS_AUD` / `ACCESS_TEAM_DOMAIN` answers 403. Unsigned identity headers are never
  trusted. Only `dev` may skip the check.
- **Invite tokens.** At least 128 bits from a CSPRNG, stored hashed, single use, expiring, bound to e-mail and role.
  Accepting consumes the token in one guarded statement.
- **First-user setup.** `/setup` creates the admin only while the user table is empty, in one guarded statement, and
  answers 404 afterwards.
- **Secrets stay server-side.** Password hashes, session hashes, invite token hashes and env values never reach
  loaders, page data, client bundles or logs.

## Soft delete and search

- **Tombstones.** Deleting sets `deleted_at`; every live-data query filters `deleted_at IS NULL`, including counts,
  mention pickers, notifications and attachment downloads. Restore clears `deleted_at` and re-indexes.
- **FTS consistency.** `pages_fts` and `tasks_fts` change only through the migration 0001 triggers. After create,
  edit, soft delete and restore, a search returns exactly the live rows. Test all four.
- **MATCH input.** User search text is escaped into a safe FTS5 expression (quote every term, strip operators and
  column filters); a malformed query returns an empty result or a 400, never a 500.
- **Revisions.** A page update and its revision row are written in the same `db.batch`. Concurrent edits compare
  `updated_at` and answer "changed meanwhile".

## Untrusted text and Markdown

- **One renderer.** Markdown is rendered only by `src/lib/shared/markdown.ts` (markdown-it, `html: false`). `{@html}`
  appears only on that module's output. Test `<script>`, `<img onerror>`, `javascript:`, `data:` and `vbscript:`
  links and images, and mixed-case and entity-encoded variants.
- **Plain text everywhere else.** Titles, task names, comments, user names and file names render as text. Strip
  control and zero-width characters and cap length before storing.
- **Mentions.** A mention resolves to an active user id on save; unknown or deactivated names stay plain text.

## Attachments (R2)

- **Server-made keys.** R2 keys are generated by the server (random id), never from user input or file names.
- **Authorised download.** Downloads go through the one route, after `requireUser` and a check that the file and its
  parent are live. Set `Content-Disposition` with a sanitised file name, `X-Content-Type-Options: nosniff`, and serve
  HTML and SVG as attachments.
- **Size and type.** The cap (25 MB) is enforced while reading the stream. The stored content type comes from an
  allowlist or falls back to `application/octet-stream`.
- **No orphans.** Write the R2 object first, then the D1 row; delete the object if the row fails. No transaction
  spans D1 and R2, so cleanup code is idempotent.

## Web and output

- **Redirects.** Use the shared safe-return helper, never a `startsWith('/')` check.
- **Form bodies.** Use the shared guard: cap the size, answer 400 or 415, never 500; prototype-safe parsing.
- **CSRF.** Mutations are POST form actions or API calls that pass SvelteKit's origin check; no state change on GET.
- **Svelte keyed lists.** Key `{#each}` by a database id or index, never by user text.
- **CSP.** Per-route additions only, never `'unsafe-inline'` for scripts.
- **Errors.** Error pages and API errors never show stack traces, SQL or file paths.

## Logging and privacy

- **Structured, minimal logs.** Log event names, ids and status codes. Never log passwords, tokens, session or invite
  values, page or comment text, attachment names, or full e-mail addresses.
- **Request ids.** Errors carry an id the user can quote; the log line holds the detail.

## UI quality

- **Truthful state.** Only a confirmed server write is shown as saved.
- **States.** Loading, empty, error, saving and success exist for every new view and form.
- **Accessibility.** Focus returns to the opener; headings never skip; touch targets at least 44 px on coarse
  pointers; AA contrast in light and dark; every control reachable by keyboard.
- **User copy.** Never contains a file path or internal identifier.

## Tests

- **Gates.** `npm run gates` (check, lint, test, build) is clean.
- **Fail-before proof.** Every regression test fails on the unfixed code; show that run.
- **Fixtures.** Seed and test data are fictional; nothing resembles a real person or customer.

## Pre-handoff probes

Run the ones that apply and list their result lines.

- **Concurrency:** 20 concurrent requests at any counter, cap, invite or "last admin" rule; the limit holds exactly.
- **Two tabs / stale forms:** state-changing forms compare `updated_at` and answer "changed meanwhile".
- **Roles:** every new route and payload crawled as signed-out, member, admin and deactivated user.
- **Soft delete:** delete then restore a row; lists, counts, search, mentions and downloads follow.
- **FTS:** search after create, edit, delete and restore matches the live rows; a 60-character term and a term full of
  quotes and operators do not fail.
- **Markdown vectors:** the XSS list above renders inert.
- **Access JWT:** missing, expired, wrong `aud`, wrong signature and wrong issuer are all refused when the Access
  variables are set.
- **360 px:** layout, touch targets, no horizontal scroll.
- **No-JS forms:** a form action's refusal or success shows without JavaScript.
